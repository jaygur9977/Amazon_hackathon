SECTION 2: WHAT CAN AND CANNOT RUN ON VERCEL
================================================================================

VERCEL LIMITATIONS:
  Vercel is a SERVERLESS platform. That means:
  - No persistent file system (files you write disappear after each request)
  - No long-running processes
  - No Python runtime for Node.js functions
  - Functions timeout after 10 seconds (free) / 60 seconds (pro)
  - No ffmpeg, no yt-dlp, no cv2/OpenCV

CANNOT WORK ON VERCEL (backend features):
  [X] Video Analysis Pipeline    — spawns Python (python3 process_clip_single.py)
  [X] Video File Streaming       — reads 74 MB of MP4 files from local disk
  [X] File Uploads (save to disk)— saves uploaded MP4s to clips/uploaded/
  [X] YouTube Ingestion (yt-dlp) — requires subprocess
  [X] Evidence frame extraction  — writes JPEG files to evidence/ folder
  [X] Writing analyzed-events.json — serverless has no persistent disk

CAN WORK ON VERCEL (backend features):
  [✓] AI Assistant Chat         — just calls Groq API (external HTTP request)
  [✓] Daily Summary             — reads from JSON files bundled in deploy
  [✓] Video list (read-only)    — reads events-all.json and analyzed-events.json
  [✓] Per-video analysis detail — reads from analyzed-events.json
  [✓] RAG question answering    — reads JSON + calls Groq API

CONCLUSION:
  The FRONTEND works 100% on Vercel.
  The BACKEND needs a real server (persistent filesystem + Python).

SECTION 3: FINAL DECISION - WHAT TO HOST ON VERCEL
================================================================================

DECISION: HOST BOTH, BUT ON DIFFERENT PLATFORMS

  FRONTEND  → Vercel (free, perfect fit)
  BACKEND   → Render.com (free, persistent server, supports Node.js)

WHY THIS IS THE BEST APPROACH:
  - Vercel is purpose-built for React/Vite frontends (CDN, edge, fast)
  - Render gives you a real server with filesystem and Python support
  - Both are FREE tier
  - This is the industry-standard "JAMstack" architecture
  - No code rewrites needed for the backend
  - Everything works: AI chat, video list, analysis, daily summary

WHAT WILL WORK AFTER DEPLOYMENT:
  [✓] All 41 video clips listed in Video Library
  [✓] Analysis detail pages for all 45 analyzed clips
  [✓] AI Assistant answering questions (via Groq)
  [✓] Daily Summary page with full digest
  [✓] Per-video forensic Q&A chat
  [✓] Dashboard stats
  [✓] Search functionality

WHAT WON'T WORK (until you add cloud storage):
  [~] Uploading new videos and running new analysis
      (backend runs on Render free tier which also has ephemeral storage)
      (existing 41 clips data is read from JSON files — works fine)
  [~] Streaming MP4 video files directly
      (thumbnails and evidence frames still show)

SECTION 5: REQUIRED CODE CHANGES
================================================================================

CHANGE 1: Make API URL configurable in frontend
-------------------------------------------------
File: site/src/services/api.ts
Line 13 — CHANGE:
  const API_BASE = '/api';
TO:
  const API_BASE = import.meta.env.VITE_API_BASE_URL || '/api';

This lets Vercel point the frontend at your Render backend URL.


CHANGE 2: Create vercel.json in site/ folder
--------------------------------------------
Create NEW file: site/vercel.json
Content:
  {
    "rewrites": [
      { "source": "/(.*)", "destination": "/index.html" }
    ]
  }

This makes React Router work correctly (all paths serve index.html).


CHANGE 3: Create .env.production in site/ folder
--------------------------------------------------
Create NEW file: site/.env.production
Content:
  VITE_API_BASE_URL=https://YOUR-APP-NAME.onrender.com/api

(Replace YOUR-APP-NAME with the actual Render app name you create in Section 7)


CHANGE 4: Update CORS in backend to allow Vercel domain
--------------------------------------------------------
File: backend/.env — ADD this line:
  CORS_ORIGINS=http://localhost:5173,https://YOUR-APP.vercel.app,https://*.vercel.app

SECTION 7: STEP-BY-STEP RENDER DEPLOY (BACKEND)
================================================================================

STEP 7.1 — Go to Render
-------------------------
URL: https://render.com
Click "Get Started for Free"
Sign up with GitHub (same GitHub account as your repo)


STEP 7.2 — Create New Web Service
-----------------------------------
1. Click "New +" → "Web Service"
2. Connect your GitHub repo: Amazon_hackathon
3. Configure these settings:

  Name             : aegisvision-backend
  Region           : Oregon (US West) or Singapore
  Branch           : main
  Root Directory   : backend          ← IMPORTANT: set this!
  Runtime          : Node
  Build Command    : npm install
  Start Command    : node server.js
  Instance Type    : Free


STEP 7.3 — Add Environment Variables on Render
------------------------------------------------
In the Render dashboard → Environment tab, add:

  Key               Value
  ---               -----
  NODE_ENV          production
  PORT              10000
  GROQ_API_KEY      (paste your actual Groq API key from backend/.env)
  CORS_ORIGINS      https://aegisvision-ai.vercel.app,http://localhost:5173
  VIDEO_ROOT        clips
  EVIDENCE_ROOT     evidence


STEP 7.4 — Wait for Deploy
----------------------------
Render will:
1. Clone your repo
2. cd into backend/
3. Run: npm install
4. Run: node server.js

Takes ~3-5 minutes first time.
You get a URL like: https://aegisvision-backend.onrender.com


STEP 7.5 — Test Backend is Alive
----------------------------------
Open in browser:
  https://aegisvision-backend.onrender.com/api/health

You should see JSON like:
  { "status": "ok", "version": "2.0.0", "has_groq_key": true }


NOTE ABOUT RENDER FREE TIER:
  - App "sleeps" after 15 minutes of inactivity
  - First request after sleep takes ~30 seconds (spin-up time)
  - This is normal for free tier
  - Upgrade to Starter ($7/month) for always-on

SECTION 12: TROUBLESHOOTING
================================================================================

PROBLEM: "Generating daily event digests..." spinner stuck
FIX: Backend not reachable. Check:
  1. Render app is running (check render.com dashboard)
  2. VITE_API_BASE_URL is set correctly in Vercel env variables
  3. CORS_ORIGINS on Render includes your Vercel domain

PROBLEM: AI Assistant says "Error connecting to AI service"
FIX: GROQ_API_KEY not set on Render
  1. Go to render.com → Your service → Environment
  2. Add GROQ_API_KEY with your actual key
  3. Save and redeploy

PROBLEM: React Router 404 on page refresh
FIX: vercel.json rewrites not set correctly
  Make sure site/vercel.json has:
  { "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }

PROBLEM: CORS error in browser console
FIX: Add your Vercel URL to CORS_ORIGINS on Render
  CORS_ORIGINS=https://aegisvision-ai.vercel.app,http://localhost:5173

PROBLEM: Render backend first request takes 30 seconds
FIX: This is normal on free tier (cold start)
  Option A: Upgrade to $7/month Starter plan
  Option B: Use UptimeRobot to ping backend every 14 min and keep it warm
  URL to ping: https://aegisvision-backend.onrender.com/api/health

PROBLEM: "Build failed" on Vercel
FIX: Check Vercel build logs. Common causes:
  1. TypeScript errors — run "npm run build" locally first and fix errors
  2. Root Directory not set to "site" in Vercel settings
  3. Missing package — run "npm install" locally first

PROBLEM: Environment variables not working
FIX: After adding env vars on Vercel, you MUST redeploy:
  vercel --prod
